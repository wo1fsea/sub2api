# 0.2.13：站点统一主题、组件覆盖与品牌标记

## 结果与范围

本轮继续使用上游 v0.2.13 的版本号，开发方向为「以 OpenJev 为参考的克制的新粗野主义」。补齐首次登录引导、公告、协议、二次验证、浮层、提示、状态矩阵等样式；保留已有图表斜线纹理及缓存。默认 Logo 和 favicon 使用同一套细框、斜线灰度、少量荧光色的 SVG，已有管理员上传的 Logo 保留。

管理员在「系统设置 → 通用设置 → 站点主题」统一设置皮肤、明暗模式和强调色。普通用户和访客继承站点配置，没有个人主题切换控件。配置保存在既有 settings 表中，不新增数据库迁移；公开接口和页面注入只暴露外观字段。管理员写入校验固定枚举和六位十六进制颜色，未提交外观字段时保留当前配置。已打开的页面在可见时每 30 秒刷新配置，切回窗口时也刷新。

## 上线步骤

1. 提交并推送已验证源码，按固定基础镜像和 linux/arm64 打包，校验镜像标签、摘要及 SHA256SUMS。
2. 对精确镜像进行独立数据库烟雾检查，确认普通用户修改主题返回 403；备份当前服务，在无外网的独立 DB/Redis/应用卷中恢复，验证现有管理员、会话、业务数据、双版本兼容和重启。
3. 新候选实例使用共享 DB/Redis，但关闭 token refresh、usage cleanup 和监控聚合。检查生产定时任务清单，确保不会出现两个后台任务执行者。
4. 先验证候选健康、登录、新前端资源和使用当前 Codex 配置 API key 的真实 Responses 完成事件。把当前版指纹 JS/CSS 加入静态兼容缓存，再验证入口能取回每个缓存资源。
5. HAProxy 平滑重载至候选。候选服务正常后停止旧的后台执行者，在保留当前应用卷的前提下以新镜像重建固定名称 `sub2api-current-app`；验证后将入口重载回新固定实例。
6. 固定新镜像摘要、提交和发布清单哈希，验证启动恢复及真实 HTTPS API。验证完成后清理候选容器/卷及旧应用镜像。保留数据库、Redis、当前应用卷、离线包、备份和旧前端静态缓存。

执行入口：`deploy/local-upgrade/upgrade-appearance.mjs prepare <manifest> <fresh-backup>`、`activate`、`cleanup`。该脚本面向本次旧镜像到新镜像的一次更替，不应在完成后重放。

## 连续服务与边界

原站点在候选通过前持续服务；候选在固定新实例重建期间持续服务。热重载保持监听端口与现有前端连接。旧指纹资源缓存支持仍打开旧页面的客户端；JWT 与业务数据沿用原 DB/Redis。切换失败时，在候选保持可用期间恢复旧应用镜像与唯一后台执行者，不回滚共享生产数据库。

长请求可能在停止旧实例的宽限期后断开，客户端需按自身重试行为重新建立请求；不承诺恢复同一条正在生成的流。上线验证包括新真实请求、会话复用和资源可读，不等于所有第三方客户端均实现了自动续接。启动恢复演练不重启用户 Mac，不能代替完整冷启动验证。
